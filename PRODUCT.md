# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users
Individual job seekers, tech-first but also nurses, analysts, marketers and others. They use
job-scout right after a search, in one sitting, to decide which few of about 15 open roles to
apply to. They come back later on reruns to see what is new, saved or closed.

## Product Purpose
job-scout is an agent skill that reads a resume, confirms a search brief, reads employer job
boards directly and returns roles that are open today. Success on the results page: the user
picks the ~3 roles worth applying to without reading everything first, then tells job-scout
what they saved, applied to or dismissed.

## Positioning
Every role is live-checked on the employer's own board, links straight to the employer, and
every fit reason is quoted from the posting and checked by a script. Unknowns stay visible
("pay not listed"). Nothing is padded.

## Operating Context
- The chat table is the main output; the HTML report (`report.html` in the run folder) is an
  extra the agent opens in a local browser.
- Read mostly on laptops and big monitors, sometimes on phones for a quick re-check.
- Feedback goes back through the chat: the report's copy buttons produce lines like
  `save 3 (Vercel, Design Engineer)`.

## Capabilities and Constraints
- The report is one self-contained HTML file generated by stdlib Python
  (`skills/job-scout/scripts/report.py`): inline CSS and JS, system fonts, no images, no network.
- A Content-Security-Policy allows only the page's own script; every value is escaped.
- The page keeps no state; `seen.json` is the only record.
- Must work with JavaScript off and print cleanly.
- Typical 15 roles, up to 60.

## Evidence on Hand
Real run data comes from the user's own searches; eval fixtures live in
`skills/job-scout/evals/`. There are no testimonials or customer claims, and none may be invented.

## Product Principles
- Answer "which roles fit me?" before "why?": the reader should not have to read everything to
  find the fits.
- Quote, never paraphrase, the posting.
- Show unknowns instead of hiding them.
- The chat stays the source of truth; the report is a faster way to look at the same results.

## Accessibility & Inclusion
WCAG 2.2 AA: real table semantics, keyboard use, visible focus, no color-only meaning,
reduced-motion respected.
